# 온체인 스크리닝 오탐 실험

거래소의 입금 검사(스크리닝) 규칙이 **원치 않은 돈을 받은 사람까지 막는지** 시험해보는 공용 저장소

## 진행 순서

| 순서 | 할 일 | 어디에 |
|---|---|---|
| 1 | 각자 규칙 만들기 | `rules/`에 올리기 |
| 2 | 각자 시나리오 2개 + 정답 쓰기 | 아직 올리지 않기 |
| 3 | 셋 다 규칙을 올리면, 시나리오 올리기 | `scenarios/`에 올리기 |
| 4 | 모든 시나리오를 모든 규칙에 돌려서 정답과 비교 | `results/`에 올리기 |

> 규칙은 남의 시나리오를 보기 전에 올리고, 올린 뒤엔 고치지 않기
> → 미리 보면 거기에 맞춰 규칙을 고치게 되니까

## 폴더

| 폴더 | 들어갈 것 |
|---|---|
| `rules/이름/` | 내가 만든 규칙 |
| `scenarios/이름/` | 내가 만든 시나리오 + 정답 |
| `results/` | 교차 테스트 결과 |

폴더는 처음 올리는 사람이 만들면 됨

## 용어

| 용어 | 뜻 |
|---|---|
| 규칙 | "이런 입금이 들어오면 이렇게 처리한다"는 판단 기준표 |
| 시나리오 | 규칙을 시험해볼 가상의 입금 상황 |
| 정답 | 시나리오 속 사람이 원래 누구인지: 무고한 사용자 / 범죄자 / 판단 불가 |

## 처리 결과

규칙은 아래 4개 중 하나를 내놓기

통과 / 확인 필요 / 자금 동결 / 계정 제한

## 규칙 A (공통 기본 규칙)

위험 주소와 연결돼 있으면 계정 제한, 아니면 통과

→ 각자 규칙이 이것보다 나은지 비교하는 기준

## 채점

| 볼 것 | 뜻 |
|---|---|
| 억울하게 막힌 수 | 무고한 사용자인데 계정 제한 (문제 된 돈만 묶는 자금 동결은 법적 의무라 제외) |
| 놓친 범죄 수 | 범죄자인데 통과 |
| 판단 보류 수 | 확인 필요로 보낸 수 |

## 시작 전에 셋이 정할 것

- [ ] 시나리오(거래 기록) 적는 양식
- [ ] 사용할 언어

## 지킬 것

- 진짜 지갑 주소는 쓰지 않기 (가짜 주소만)
